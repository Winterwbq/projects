# Zapdos Input Package

This file describes the MC-to-Zapdos input files generated by:

```bash
python scripts/prepare_zapdos_inputs.py --config config/case.yaml --out runs/zapdos_initial_input
```

The files are also written during each coupling iteration under:

```text
runs/demo/zapdos_input/iter_0001/
runs/demo/zapdos_input/iter_0002/
...
```

## Required Values for Zapdos

Zapdos needs these values from the MC/coupler:

```text
n_Cu(r,z)          neutral copper density [m^-3]
S_iz_Cu(r,z)       copper ionization source [m^-3 s^-1]
B_total(r,z)       total magnetic field [T]
target bias        powered target boundary voltage [V]
plasma guess       initial potential estimate [V]
boundary fluxes    target/wafer/wall Cu flux estimates
target source      sputtered neutral Cu source [m^-2 s^-1]
```

The current generated package contains the following files.

## `mc_fields.csv`

Cell-centered volume fields on the common axisymmetric `r-z` mesh.

Columns:

```text
r_m                 radial coordinate [m]
z_m                 axial coordinate [m]
n_Cu_m3             neutral Cu density from MC [m^-3]
S_iz_Cu_m3_s        Cu ionization source [m^-3 s^-1]
Br_T                radial B_total component [T]
Btheta_T            azimuthal B_total component [T]
Bz_T                axial B_total component [T]
Bmag_T              |B_total| [T]
```

For Zapdos, the most important columns are:

```text
n_Cu_m3
S_iz_Cu_m3_s
Br_T, Btheta_T, Bz_T
```

## `target_source.csv`

Radial target source profile.

Columns:

```text
r_m                       radial coordinate [m]
Gamma_Cu_target_m2_s      sputtered neutral Cu source [m^-2 s^-1]
```

This is mainly needed if Zapdos applies source or boundary terms at the target.

## `boundary_fluxes.csv`

Radial estimates of Cu fluxes to target and wafer.

Columns:

```text
r_m                              radial coordinate [m]
Gamma_Cu0_target_return_m2_s     neutral Cu return flux to target [m^-2 s^-1]
Gamma_Cu0_wafer_m2_s             neutral Cu wafer flux [m^-2 s^-1]
Gamma_Cuplus_target_m2_s         Cu+ target flux [m^-2 s^-1]
Gamma_Cuplus_wafer_m2_s          Cu+ wafer flux [m^-2 s^-1]
```

During the initial preparation step, Cu+ fluxes are zero because the first Cu+ MC solve has not run yet. After coupled iterations, these columns are filled from MC ion tallies.

## `wall_losses.csv`

Total wall loss rates.

Columns:

```text
species        Cu0 or Cuplus
loss_rate_s    total particle loss rate to wall [s^-1]
```

These can be used for global balance checks or wall-loss boundary conditions.

## `operation.csv`

Operating condition scalars.

Columns:

```text
target_bias_V
plasma_potential_guess_V
target_current_A
target_power_W
wafer_rf_amplitude_V
wafer_rf_frequency_Hz
wafer_rf_ramp_time_s
pressure_Ar_Torr
```

`pressure_Ar_Torr` is retained as an operating-condition record. In the
Cu-dominant Zapdos template, electron transport uses local Cu vapor pressure
computed from `n_Cu_m3`, not this Ar pressure.

## `mesh.csv`

Cell-centered mesh information.

Columns:

```text
index_r
index_z
r_center_m
z_center_m
cell_volume_m3
```

Use this file to verify that Zapdos and MC are interpolating fields on the same coordinate convention.

## `zapdos_input_manifest.yaml`

Machine-readable summary of the package, including:

```text
coordinate system
mesh dimensions
file names
units
operation settings
field definitions
```

## Suggested Zapdos Usage

At minimum, map these fields into Zapdos:

```text
n_Cu_m3          -> neutral Cu density material/property/aux variable
S_iz_Cu_m3_s     -> Cu ionization source term; convert particles to moles in Zapdos if use_moles=true
Br_T/Btheta_T/Bz_T -> magnetic field vector
target_bias_V    -> target potential boundary condition
```

Then Zapdos should output back to MC:

```text
phi(r,z)
Er(r,z), Ez(r,z) or phi so MC can compute E = -grad(phi)
ne(r,z)
Te(r,z) or mean_energy(r,z)
optional S_iz_Zapdos(r,z)
```
